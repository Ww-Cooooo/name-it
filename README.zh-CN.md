# Name It

> 把复杂想法压成一个短、准、好记的名字。

Name It 是一个面向 Codex 的公开 Skill，用来给项目、产品、工具、Agent、Skill、功能、工作流、仓库和软件包起名或改名。

当一个名字太长、太含糊、记不住、容易误解，或者已经和实际功能对不上时，它会先理解这个东西到底是做什么的，再给出一个明确首选和少量真正不同的备选。它不会一次扔出几十个随机名字，让用户自己从一堆近义词里筛选。

## 它会做什么

- 找出名字最应该传达的核心含义；
- 平衡清楚、简短、准确、好记和有辨识度；
- 先给一个首选，再给少量有意义的备选；
- 可以直接比较用户已经想到的名字，不会动不动推倒重来；
- 记住“太长”“太抽象”“不像这个产品”等反馈并继续收敛；
- 面向双语受众时检查读法、含义和可能的误解；
- 把起名判断和联网重名、商标核查清楚地区分开。

Name It 不会为了显得专业而生造缩写，也不会把一次起名做成一套沉重的品牌咨询流程。

## 为什么正式 Skill 使用英文

安装并被发现后，Codex 加载的正式入口 [SKILL.md](SKILL.md) 使用英文；仓库同时提供中英文 README。这样只维护一份正式指令，避免两套规则逐渐漂移。

Skill 默认使用当前对话的语言回答；如果要起英文名、中文名或双语名，则按照实际命名对象调整。

Name It 当前以 Codex 为正式目标。其他兼容 Agent Skill 结构的宿主可能可以读取它，但在完成真实验证前不承诺跨宿主兼容。

## 什么时候使用

适合这些情况：

- 给新项目、产品、应用、工具、Agent、Skill 或功能起名；
- 把一个很长的暂定名压缩下来，但不丢掉核心含义；
- 让别人第一眼更容易明白它大概是做什么的；
- 从几个已有候选中选出最合适的一个；
- 原来的名字已经和当前能力不符，需要重新命名；
- 确定最终大小写、空格、仓库名或软件包名。

普通变量名、函数名和单纯翻译一个已经确定的名称，通常不需要使用这个 Skill；除非其中确实包含重要的命名取舍。

## 使用示例

```text
使用 $name-it 给这个公开 Codex Skill 起名。它让 Codex 把问题想全面，但不会把小项目做成中大型企业系统。我想要一个简短、别人第一眼大概能看懂的英文名。先推荐一个，再给少量真正不同的备选。
```

它会先给出最推荐的名字，说明为什么合适，再展示少量备选及真实取舍；如果还没有做联网重名检查，也会明确告诉用户。

## 安装

仓库公开后，如果希望 Codex 直接安装，可以把下面这段请求发给它：

```text
请检查并安装这个 Codex Skill：https://github.com/Ww-Cooooo/name-it
只授权检查并把这个仓库复制到我的个人 Skill 目录；不要安装依赖、修改项目，也不要覆盖、删除或更新已经存在的 Skill。如果目标已经存在，停止并报告它的路径和来源。
安装完成后告诉我实际位置和复制了什么。我会另外打开一个新任务验证是否发现 $name-it。
```

也可以手动克隆。需要本机已经安装 Git，并且目标 `name-it` 目录尚不存在。

### Windows PowerShell 7

```powershell
$skillRoot = Join-Path $env:USERPROFILE ".agents\skills"
New-Item -ItemType Directory -Force -Path $skillRoot | Out-Null
git clone https://github.com/Ww-Cooooo/name-it.git (Join-Path $skillRoot "name-it")
```

### macOS 或 Linux

```bash
mkdir -p "$HOME/.agents/skills"
git clone https://github.com/Ww-Cooooo/name-it.git "$HOME/.agents/skills/name-it"
```

安装后打开一个新的 Codex 任务，让它确认 `name-it` 已出现在当前可用 Skill 列表中，并报告实际解析到的 `SKILL.md` 路径。需要某次起名任务确定使用它时，可以显式写出 `$name-it`。

## 边界

- 不会扩大用户授予 Codex 的权限；
- 未经请求和授权，不会自动联网；
- 普通网页搜索只能发现明显重名，不能替代正式商标审查；
- 没有实际查询对应平台时，不会声称域名、账号、仓库名或软件包名可用；
- 不会自动把起名扩展成完整品牌战略、视觉系统或法律服务；
- 当前仓库只包含 Skill 指令、展示信息和三个由提示与预期结果组成的测试夹具，不包含可执行脚本或依赖。
